- Add `chunkdb_restore --table t [--as name] [--area cx0 cy0 TO cx1 cy1] [--allow-split] <backup> <data-dir>`, which adds one table of a backup offline to an existing or new data directory as a new table with a new epoch and lineage, as RESTORE TABLE does; a fresh data directory is prepared privately and published once complete; `--area` restores only the chunks in the range and drops the coordinate-index records outside it, and refuses an area that holds only some chunks of a commit, naming its revisions, unless `--allow-split` is given, which prints them; `chunkdb_restore <backup> <data-dir>` is unchanged (#149).
- Add `chunkdb_admin --data-dir <dir> quarantine --table t --chunk cx cy [cz] [--force]`, which sets a damaged chunk aside offline so its table opens without it: it moves the chunk's image and WAL into the table's `.chunkdb.quarantine/` directory with a synced `quarantine.record`, marks the table's slots to resync, refuses a chunk that passes the `chunkdb_verify` checks without `--force` and a chunk a pending recovery intent needs, and finishes an interrupted run after verifying the saved copies; `chunkdb_verify` lists quarantined chunks (#149).
- Add `BACKUP TO 'x' SKIP DAMAGED`, which leaves out each chunk whose image or WAL fails the `chunkdb_verify` checks instead of refusing the backup: the reply adds `skipped` with each chunk's table, coordinates, file, code and detail, the completion record `chunkdb.backup` lists them in version 2 (a backup without skipped chunks keeps version 1), `chunkdb_verify` reports each as warning `backup_chunk_skipped`, and a restore of that backup has no data for them (#149).
- Add `CHECK TABLE t [CHUNK c | AREA a TO b | AREA AROUND c RADIUS r]`, with ADMIN on the table or MONITOR, which runs the `chunkdb_verify` checks on the image and WAL of each chunk with files while the table serves and replies with the chunks checked and each damaged chunk, its file, code and detail: one chunk is checked at a time, so only statements on that chunk wait; CANCEL, KILL CONNECTION, statement timeouts and shutdown stop it, including during listing and WAL replay, and SHOW CONNECTIONS shows its progress in chunks (#149).

- Add server-wide byte limits across all tables, each off by default: `--cache-max-bytes` evicts the coldest cached chunks of any table, as `--max-loaded-chunks` does, measuring a chunk when it loads and at each checkpoint; `--feed-total-bytes` bounds every table's live feed history together, a table dropping its own oldest history first and its watches resyncing when a change still does not fit; `--txn-history-total-bytes` bounds the chunk states kept for open transactions, a write that must keep one ending the oldest transactions of its own table with `CONFLICT reason=history_limit`. `--min-free-disk-bytes` refuses SET BLOCK, DELETE BLOCK, SET CHUNK, a COMMIT with writes, CREATE TABLE, RESTORE TABLE and MIGRATE with `DISK_FULL reason=min_free_disk` while the data directory's file system has less space available, and the table option `max_disk_bytes` (manifest option type 12, shown by DESCRIBE when set, `0` removes it; a build without the option refuses to open a table that sets it) refuses that table's data writes with `DISK_FULL reason=max_disk_bytes` once its files reach it; both are sampled at startup and every `--disk-check-ms` (1000) by one background thread, so a write checks one atomic flag. A transaction frame that fails with ENOSPC now answers `DISK_FULL` instead of INTERNAL; a file or directory sync that fails during FLUSH WAL answers `OUTCOME_UNKNOWN stage=barrier_sync` and leaves the table fail-closed until RECOVER TABLE or a restart instead of letting a retried sync report the writes durable; an eviction whose WAL cannot be cut back answers INTERNAL instead of the write error; the durability contract lists what a full disk does to writes, FLUSH WAL, COMMIT and checkpoints in each mode (#149).

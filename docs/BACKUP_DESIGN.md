# Online backup: design

`BACKUP TO '/path'` creates a server-filesystem backup (#66). The destination is absent or empty and outside the source tree; symlinks and unsafe entries are refused. MANAGES USERS is required (auth none keeps its existing unrestricted semantics). Only a single-process read-write catalog supports backup: another process can change files outside these in-process holds. One backup owns a nonblocking catalog-wide guard; another gets BUSY. The reply is a map with per-table epoch/revision cuts and table/file/byte counts. A cancellation callback checks shutdown and disconnect while pinning and copying, including TLS closure. Failure leaves an incomplete marker, never an accepted backup.

## Cut and pin

DDL holds the catalog operations mutex only through pinning. Each table has a backup pin acquired while open; exclusive table operations wait for these pins *before* publishing Busy, so pending slot management cannot stop ordinary writes. Each store has a maintenance gate: checkpoints, empty collection and archive moves take its shared side by try-lock; backup takes the exclusive side. Contending checkpoints defer rather than wait while holding a chunk lock. Existing checkpoints finish before the gate is acquired. Deferred scheduling remains armed for a later pass.

Every mutation registers a completion bound before reserving its revision, under a per-store completion mutex, and unregisters only when its entire write scope ends, including transaction postcommit durability bookkeeping after releasing chunk locks. With the maintenance gate held, sample S = next revision minus one under that same completion mutex and wait on the completion condition until all bounds <=S have cleared. Later writers register bounds >S and continue. Then retain strong references to all cached chunks in one flattened snapshot and flush their WAL batches under ordinary chunk mutexes, with cache/catalog registry locks released. Errors, durability poison, snapshot-generation failure or a chunk with failed WAL repair abort. All mutations load and lock their chunks before reserving revisions; transactions lock every target before their one revision. Eviction flushes batches before discarding unpinned chunks and cannot discard retained pending batches. Server transactions are bound to their first table, so a cut cannot split a cross-table transaction.

Images are atomically replaced, never rewritten in place. WALs append, and rollback/recovery only trim a tail. With replacement/collection blocked and all <=S writers finished, no trim can change a valid <=S prefix. Enumerate live coordinates without holding cache registry locks. Load each cold chunk through normal recovery, then under its ordinary chunk mutex flush its batch and validate its stable WAL over its image with ReplayWal and accepted frame boundaries. Select the exact last frame end <=S and hard-link image/WAL into a unique `.chunkdb.backups/<id>/` staging tree inside the data directory before unlocking. Record that required byte end and the observed file bound. This moves prefix selection into pinning instead of trimming a mutable suffix at leisure: it uses ordinary per-chunk locks, while writes to other chunks continue; no table Busy or exclusive writer gate is used. New files created after S contain only later revisions. Record the frozen table manifest (including schema history), a clock ceiling above S, initialized marker and slot metadata; serialize a stable even snapshot generation for the independently frozen copy. Copy catalog metadata and an atomic users snapshot. Then release table pins, DDL and maintenance gates.

Copy each pinned WAL exactly through its already validated <=S end, without inspecting its mutable >S suffix. Later rollback may shorten only that suffix. A truncation inside the required prefix fails closed. Full replay validation and crash-tail classification happen under the chunk lock before pinning; true damage fails, and ordinary crash tails are excluded. Copy only this prefix and images, including images of empty state when present; a header without a needed frame may be omitted. Never copy feed archives, lock/heartbeat files, dropped/staging table artifacts or foreign entries. Hard links keep images and old WAL inodes alive after normal checkpoint/GC resumes.

## Intents and metadata

A rollback intent <=S must have completed repair before its chunk locks can be visited; if repair failed, the store is poisoned and backup fails. A retained committed intent has the same replay outcome as no intent, and every transaction frame is included or excluded together. Conditional rollback markers follow the same chunk lock rule. Intents of >S operations govern only excluded frames. Consequently the derived cut needs no intent files; it carries all committed <=S effects with no pending rollback. Slot records preserve names and loss state, clamping written/durable positions to S; archives are deliberately excluded because restore resets consumption to S.

Copy in bounded blocks with cancellation checks. Sync every copied file, directory and destination parent. The incomplete guard is durable before data is published. Write `chunkdb.backup` last: version, timestamp, table names/S/epochs and an inventory of relative paths, lengths and CRC32 values, itself CRC32 protected. Removing the incomplete guard is the completion point, after the marker and directory are synced. A backup directory is refused by server/store open even when complete; `chunkdb_verify` validates marker, inventory and ordinary table-set storage without mutation. Unknown, missing, changed or unsafe entries fail validation. Cross-check the exact table set/epochs/cuts, all image and WAL revisions <=S, clock ceilings >S, slot positions <=S, even snapshot generations, initialized markers and users decoded by DecodeUsers; reject intents and feed archives. Aborted staging is private and removable on next startup; an abandoned target stays explicitly incomplete.

## Restore and crashes

`chunkdb_restore <backup> <data-dir>` requires an absent/empty target outside the backup and verifies it before publication. Build a sibling temporary directory under a durable restore-incomplete guard. Copy the verified cut, choose a new store id per table, rewrite manifests with existing serializers and validated image/WAL headers only (store id and header CRC), preserving historical image schema/layout, compression, optional sections and original WAL feature flags, and keep the clock above S. Reset every retained slot to the new epoch at S (including previously lost names, now a fresh baseline); keep no archives. A consumer presenting its old epoch gets resync. Two restores choose distinct epochs.

Sync rewritten files and the whole tree; remove the backup marker only in this guarded temporary tree. Rename to the target using an atomic exclusive-directory rename; refuse platforms without that primitive rather than using an unlocked check-then-rename fallback, sync its parent, and remove/sync the restore guard last. A crash before that last completion leaves an absent target or a guarded directory the server refuses. At completion the entire new-epoch data directory is ready to open. Source backup and live data are never changed by restore. Backup crash boundaries before completion leave an incomplete target; after completion they leave a fully verifiable backup. Child-process failpoints cover publication, pinning, copy/sync, marker and both restore publication boundaries.

## Checks

Concurrent acknowledged block/chunk/conditional/transaction/delete writes in relaxed and fsync-wal, ALTER plus checkpoint/GC, compare restored state with acknowledged <=S log; verify no >S state. Test rights, BUSY, targets, disconnect, backup-open refusal, verifier, repeated restore/new-epoch slot resync and crashes at each durable boundary. WERROR and targeted tests plus TSan on new concurrency tests; no hot-path measurements.

# Online backup: design

`BACKUP TO '/path'` creates a server-filesystem backup (#66). The destination is absent or empty and outside the source tree; symlinks and unsafe entries are refused. MANAGES USERS is required (auth none keeps its existing unrestricted semantics). One backup owns a nonblocking catalog-wide guard; another gets BUSY. The reply is a map with per-table epoch/revision cuts and table/file/byte counts. A cancellation callback checks shutdown and disconnect while pinning and copying, including TLS closure. Failure leaves an incomplete marker, never an accepted backup.

## Cut and pin

DDL holds the catalog operations mutex only through pinning. Each table has a backup pin acquired while open; exclusive table operations wait for these pins *before* publishing Busy, so pending slot management cannot stop ordinary writes. Each store has a maintenance gate: checkpoints, empty collection and archive moves take its shared side by try-lock; backup takes the exclusive side. Contending checkpoints defer rather than wait while holding a chunk lock. Existing checkpoints finish before the gate is acquired. Deferred scheduling remains armed for a later pass.

With the gate held, record S = next revision minus one and retain strong references to all cached chunks that exist before S. Flush every retained chunk's WAL batch under its ordinary chunk mutex; errors and durability-poisoned stores abort. All mutations reserve revisions after loading and locking their chunks; transactions load and lock all affected chunks before reserving their one revision. Therefore every mutation at or below S has finished or rolled back when these locks have been visited; later writes can continue, and eviction cannot discard retained pending batches. Server transactions are bound to their first table, so a cut cannot split a cross-table transaction.

Images are atomically replaced, never rewritten in place. WALs append, and rollback/recovery only trim a tail. With replacement/collection blocked and all <=S writers finished, no trim can change a valid <=S prefix. Hard-link live images and WALs into a unique `.chunkdb.backups/<id>/` staging tree inside the data directory, recording each WAL's observed byte bound. New files created after S contain only later revisions. Record the frozen table manifest (including schema history), a clock ceiling above S, initialized marker and slot metadata; serialize a stable even snapshot generation for the independently frozen copy. Copy catalog metadata and an atomic users snapshot. Then release table pins, DDL and maintenance gates.

Read pinned WALs up to their recorded bound, allowing a later >S rollback to shorten that bound. Reuse full replay validation and crash-tail classification to select the last complete frame <=S over the linked image. Ignore later frames; reject damage in the required prefix. A truncation inside the required prefix fails closed. Copy only this prefix and images, including images of empty state when present; a header without a needed frame may be omitted. Never copy feed archives, lock/heartbeat files, dropped/staging table artifacts or foreign entries. Hard links keep images and old WAL inodes alive after normal checkpoint/GC resumes.

## Intents and metadata

A rollback intent <=S must have completed repair before its chunk locks can be visited; if repair failed, the store is poisoned and backup fails. A retained committed intent has the same replay outcome as no intent, and every transaction frame is included or excluded together. Conditional rollback markers follow the same chunk lock rule. Intents of >S operations govern only excluded frames. Consequently the derived cut needs no intent files; it carries all committed <=S effects with no pending rollback. Slot records preserve names and loss state, clamping written/durable positions to S; archives are deliberately excluded because restore resets consumption to S.

Copy in bounded blocks with cancellation checks. Sync every copied file, directory and destination parent. The incomplete guard is durable before data is published. Write `chunkdb.backup` last: version, timestamp, table names/S/epochs and an inventory of relative paths, lengths and CRC32 values, itself CRC32 protected. Removing the incomplete guard is the completion point, after the marker and directory are synced. A backup directory is refused by server/store open even when complete; `chunkdb_verify` validates marker, inventory and ordinary table-set storage without mutation. Unknown, missing, changed or unsafe entries fail validation. Aborted staging is private and removable on next startup; an abandoned target stays explicitly incomplete.

## Restore and crashes

`chunkdb_restore <backup> <data-dir>` requires an absent/empty target outside the backup and verifies it before publication. Build a sibling temporary directory under a durable restore-incomplete guard. Copy the verified cut, choose a new store id per table, rewrite manifest/image/WAL store ids and affected checksums using existing serializers, and keep the clock above S. Reset every retained slot to the new epoch at S (including previously lost names, now a fresh baseline); keep no archives. A consumer presenting its old epoch gets resync. Two restores choose distinct epochs.

Sync rewritten files and the whole tree; remove the backup marker only in this guarded temporary tree. Rename to the target without replacing an occupied path, sync its parent, and remove/sync the restore guard last. A crash before that last completion leaves an absent target or a guarded directory the server refuses. At completion the entire new-epoch data directory is ready to open. Source backup and live data are never changed by restore. Backup crash boundaries before completion leave an incomplete target; after completion they leave a fully verifiable backup. Child-process failpoints cover publication, pinning, copy/sync, marker and both restore publication boundaries.

## Checks

Concurrent acknowledged block/chunk/conditional/transaction/delete writes in relaxed and fsync-wal, ALTER plus checkpoint/GC, compare restored state with acknowledged <=S log; verify no >S state. Test rights, BUSY, targets, disconnect, backup-open refusal, verifier, repeated restore/new-epoch slot resync and crashes at each durable boundary. WERROR and targeted tests plus TSan on new concurrency tests; no hot-path measurements.

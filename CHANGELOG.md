# Changelog

## Unreleased

- Add partitioned slots: `CREATE SLOT 's' ON t ... PARTITIONS n` splits a slot into 1 to 256 partitions by a fixed hash of the chunk coordinates, and `WATCH t SLOT 's' PARTITION p, ...` holds some of them, so several watches share one slot; each change of a chunk goes to the watch holding its partition, a change of several partitions reaches each watch with its own chunks under the same revision, and a watch without PARTITION holds every partition. Each partition keeps its own acknowledged position: ACK saves it for the watch's partitions, a watch starts at the lowest of its partitions and skips what each acknowledged, and SHOW SLOTS adds `partitions`, one `{partition, acked, attached}` map per partition, with `acked` the lowest of them. A watch asking for a held partition receives SLOT_BUSY, and TAKEOVER replaces the one watch holding them. `chunkdb.slots` gains header flag `0x4` with a partition count for each slot and a position and resync flag for each partition, owned by the new table feature `slot_partitions` (incompat bit `0x100`), which new directories enable; existing slots keep their records, and MIGRATE refuses PARTITIONS. CREATE SLOT refuses with OUT_OF_RANGE a slot that would take the table's slot records past 1024 slots or 1 MiB, about 450 slots of 256 partitions, instead of failing as damaged records (#156).
- `--listen-uri` takes port 0 as `--port` does; `chunkdb_exporter --listen host:0` listens on a free port, which the `port` field of its INFO line `serving metrics` names, now written at once; `chunkdb_server_bench --server-mode spawn --port 0` starts its server on a free port and reports that port (#130).
- A float literal compared with an f32 value in a condition is rounded to the nearest f32, as an f32 `$n` is, so `IF f = 0.1`, `WHERE f = 0.1` and `CHECK (f <> 0.1)` see a stored 0.1 as equal; before, the literal stayed f64 and missed it. This holds for IF, the WHERE of AGGREGATE and SCAN CHUNKS, and CHECK, also the checks of existing tables; arithmetic with a float literal, assignments, integer literals and f64 columns are unchanged, and a finite literal beyond f32 keeps its value (#297).
- A float literal in the subnormal range, such as `1e-310`, reads as its nearest f64 on every platform, and one below it as zero; before, some platforms refused it as not a number. A literal beyond the f64 range, such as `1e999`, is still refused with SYNTAX, now saying it is beyond the f64 range (#297).
- Trailing options are accepted in any order, as the CQL reference says: GET BLOCK and GET AREA take COLUMNS after WITH, LIMIT, AFTER or SCALE, SHOW SLOTS takes PREFIX before ON, and CREATE USER takes REQUIRE CHANNEL BINDING before MANAGES USERS; a repeated option is refused with SYNTAX (#297).
- A table, column, user or check named `if` can be dropped and altered: IF starts IF [NOT] EXISTS only when NOT or EXISTS follows it, so `DROP TABLE if` and `ALTER TABLE t DROP COLUMN if` read `if` as the name (#297).
- SYNTAX errors escape bytes of 0x80 and above as `\xHH`, as they did control bytes, so an error reply is ASCII and valid UTF-8 whatever the statement held; before, a statement with a non-ASCII byte where no token may start got an error reply with that byte alone (#297).
- The refusal of a statement inside a transaction lists SHOW CONNECTIONS, CANCEL and KILL CONNECTION, which run there (#297).
- The CQL reference says that arithmetic chains from left to right and only comparisons do not chain (#297).
- SHOW CONNECTIONS reserves the encoded size of its listing after building it, from an output reserve of its own, instead of reserving twice its 1 MiB response ceiling from the reserve that login and error replies use for as long as its reply was written; a listing that reserve cannot hold receives `BUSY reason=reply_budget` (#287).
- Loading a chunk, backup checks and `chunkdb_verify` check text and bytes values after every WAL frame, as feed replay does, instead of only in the state replay ends in; a backup links or admits coordinate-index entries only after the inventory's checksum and length are checked; a start refused by its option flags or by a later table no longer drops an interrupted narrowing or ADD CHECK from a manifest first, which now happens only once every table passed its checks (#282).
- `chunkdb.users` is at most 64 MiB and the backup record `chunkdb.backup` at most 1 GiB: writers refuse larger files and readers check the size before they read one whole (#282).
- `chunkdb_admin reset-password` refuses a data directory with a feature this build can only read before it recovers or writes anything, as `rebuild-version-clock` and a read-write open do (#282).
- The SCRAM challenge for an unknown user takes its iteration count and salt length from the verifier of an existing user, chosen by the name, instead of always 4096 iterations and a 16-byte salt, so it looks like the challenge of a user who exists when users have other parameters (#287).
- `chunkdb_verify` reports commit group owner files in a data directory or table, which this build never creates, as `group_owner_unclaimed` warnings instead of `unexpected_entry`, `foreign_entry` or no finding (#136).
- A failed close of a file or directory descriptor after a sync or an atomic write is no longer retried or repeated: the descriptor is closed exactly once and the failure, an interrupted close included, is returned; before, a retried close could close a descriptor another thread had just opened (#282).
- The durability contract states that `fsync-checkpoint` behaves as `fsync-wal`: both sync the WAL before a write returns and a checkpoint's image before it removes a WAL; it described `fsync-checkpoint` as a different mode (#282).
- `--port 0` listens on a free port the system picks; the INFO line `ready to accept connections` names it in its `port` field and is now written out at once, also when standard output is a pipe or file (#130).
- Add `WATCH CATALOG`, a feed of table, user and slot changes for MONITOR or ADMIN on `*`: it answers `{epoch, revision}` with a catalog epoch for the server process, then sends `[catalog, epoch, revision, commit_time_ms, user, events, txn]` pushes, the first holding the whole catalog and each later one what one statement changed, with events `{kind, action, name, table, data}` of kind `table` (the DESCRIBE map without `revision`), `user` (the SHOW USERS map, so grants appear as user changes) or `slot` (filters and owner) and action `create`, `alter` or `drop`; users, slot owners and the statement's user appear only with MANAGES USERS, a watch more than `--feed-buffer-bytes` of catalog events behind receives `resync` and the whole catalog again, catalog watches count against `--max-watches`, WATCH on a connection that already watches is refused with INVALID_ARGUMENT, a cancelled or timed-out statement does not end catalog watches, a table that cannot be read without waiting keeps its records until a later event, losing the rights ends the watch with PERMISSION_DENIED, a server that shares its data directory with other processes refuses it, CREATE TABLE, RENAME TO and RESTORE TABLE refuse the table name `catalog`, the catalog revision is not stored, so consumers watch again after a restart and rebuild from the first push, and HELLO adds feature `watch_catalog`; without a catalog watch nothing is read or kept (#146).
- A SIGTERM or SIGINT that arrives while the server starts ends it: a stop between binding the client listener and serving it was lost, and the server kept running.
- Add `chunkdb_exporter`, which logs in to a server as a user with the MONITOR right (SCRAM, password from `--password-file`, `chunks://` with certificate verification and channel binding), reads SHOW METRICS on each scrape and serves it at `GET` and `HEAD /metrics` on `--listen` (`127.0.0.1:14242`; another address needs `--allow-remote`) with `chunkdb_up`, answering `503` with `chunkdb_up 0` when the server cannot be read; a kept connection that fails is replaced within the same scrape, a failed login is not tried again for 1 to 30 seconds, the password file must be readable by its owner only, scrapes that arrive during a read share it and ships in the release archives and the Docker image (#149).
- The table storage metrics of SHOW METRICS, such as `chunkdb_checkpoints_total` and `chunkdb_open_wal_streams`, and the transaction history metrics `chunkdb_txn_history_bytes`, `chunkdb_txn_history_copies_total` and `chunkdb_txn_history_copied_bytes_total`, have one sample per table with a `table` label instead of one sum over the tables, and SHOW METRICS leaves out a table that an exclusive statement such as ALTER TABLE holds or waits for, or a failed one, instead of waiting for it or failing (#149).
- Lines sent after WATCH before its reply are read by the watch stream, so a statement other than UNWATCH or ACK among them receives PROTOCOL and closes, as during a watch; before, they could run as ordinary statements, each adding to the server's watch count, so that `--max-watches` later refused watches the server did not have. A watch is counted once, and WATCH on a session that already has a watch receives INVALID_ARGUMENT (#287).
- A conditional write rejected after its frame reached the WAL in a relaxed-mode table now syncs the WAL truncation before it removes its rollback intent, as a rolled-back transaction does; before, a power loss could keep the rejected frame with no intent left to cut it off (#282).
- A transaction COMMIT or a conditional write in a relaxed-mode table that had seen no FLUSH WAL, slot pass or reopen since it was created now sets the FLUSH WAL durability floor, so a later checkpoint syncs its image before it removes the WAL holding the commit; before, a power loss after that checkpoint could lose the committed transaction (#282).
- A READ ONLY scan, a backup cut and the change feed no longer wait for a committed transaction to remove its intent and run its inline checkpoints, up to one per written chunk, after its outcome is settled (#136).
- SCAN CHUNKS ... SINCE and SCAN CHUNKS in a READ ONLY transaction take one step per run of up to 64 chunks that did not change after the revision instead of reading the revision of every chunk after the cursor; a page still visits every chunk of each changed run it crosses, so changes spread one per run save nothing. A write raises its run's bound with one compare-and-swap and takes no lock. `chunkdb_large_world_bench --scenario scan-pages` times each page of the current, SINCE, WITH DATA and READ ONLY passes (#26, #147).
- SET BLOCK and DELETE BLOCK take `RETURNING [OLD | NEW] (* | column, ...)` and then answer `{applied, version, rows}` with rows `[x, y(, z), values...]`: NEW, SET's default, is the block after the write and OLD, DELETE's default and only form, the block before it; the row is read under the write's lock, or from the transaction's view inside a transaction, where it counts as a read of the chunk; a false condition or IF VERSION mismatch answers `applied` false with no rows instead of an error; rows over `max_returning_rows` (65536) or the response bound refuse the write with `OUT_OF_RANGE reason=returning_limit` before it changes anything; the reply is encoded row by row and written under the reply progress deadline after the lock is released; HELLO adds the feature `returning`; writes without RETURNING keep their path and reply (#145).
- Add CHECK constraints: `CHECK [name] (condition)` on a column or after the columns of CREATE TABLE, `ALTER TABLE t ADD CHECK [name] (condition)` and `DROP CHECK [IF EXISTS] name`, over the block's columns and position; a write that leaves a block for which a check is false is refused with `CHECK_FAILED check=name`, NULL passes, SET BLOCK, SET CHUNK, transactions (at the statement and at COMMIT) and MIGRATE enforce them, ADD CHECK first evaluates every stored block and refuses with the first that fails, DESCRIBE lists `checks`, and a table without checks evaluates nothing; manifests gain schema change kinds 7 and 8, check tag 4 and ADD CHECK tag 3 (#145).
- Add `BEGIN READ ONLY`: a transaction that reads one snapshot with GET, AGGREGATE and SCAN CHUNKS without SINCE, refuses SET BLOCK, DELETE BLOCK and SET CHUNK, keeps no read set so `--txn-max-read-chunks` does not bound it, and ends with COMMIT or ROLLBACK without a conflict check; `--txn-max-duration-ms` and `--txn-history-bytes` bound it with CONFLICT reason=duration or history_limit, which frees the states kept for it. Its SCAN CHUNKS pages list the chunks populated at the snapshot, also those emptied since, with the snapshot's revision as `position`, and its first SCAN CHUNKS waits for the writes its snapshot includes. SHOW METRICS adds `chunkdb_txn_history_copies_total`, `chunkdb_txn_history_copied_bytes_total` and `chunkdb_txn_history_bytes`, the chunk states writes copy for open snapshots; HELLO adds feature `read_only_transactions` (#148).
- SET BLOCK values may be expressions over the block, such as `coins = coins + $1` or `n = COALESCE(n, 0) + 1`, and SET BLOCK and DELETE BLOCK take `IF <condition>`, such as `IF stock > 0 AND EXISTS`; the condition and values read the block under the lock of the write, so check and write are one step; a false or unknown condition answers `CONDITION_FAILED current=<version>` and changes nothing; a computed value outside its column is OUT_OF_RANGE and NULL for a column without NULL is INVALID_ARGUMENT; `NOW()` is the commit time; inside a transaction conditions read the transaction's view and count as reads at COMMIT, and `NOW()` is refused; values that read the block count as reads too, and a refused statement takes none of the transaction's write room; `IF VERSION $n` takes the version from a u64 parameter; statements with single values and no condition parse and write as before (#145).
- Add server rights MONITOR, BACKUP and REPLICATION, granted ON *: MONITOR runs SHOW METRICS, SHOW STATUS, SHOW TABLE STATS and SHOW SLOTS on every table and lists every connection, BACKUP runs BACKUP TO and RESTORE TABLE without MANAGES USERS, and REPLICATION is stored for the replication statements to come; add prefix grants such as `GRANT ADMIN ON tenant1_* TO t1` for every table starting with the prefix, kept when such a table is dropped; CREATE TABLE needs ADMIN on the new name, a matching prefix or `*` instead of ADMIN on `*`, as the new name of ALTER TABLE ... RENAME TO does, and a rename leaves prefix grants in place; SHOW USERS lists prefix grants as `prefix*` and adds `server_rights`; RESTORE TABLE by a BACKUP user needs ADMIN on the new name; SHOW METRICS and SHOW STATUS refusals name `MONITOR or ADMIN on *`, BACKUP TO refusals `BACKUP or MANAGES USERS`, RESTORE TABLE refusals `BACKUP, MANAGES USERS or ADMIN on *` or the new name, and CREATE TABLE refusals the table; `chunkdb.users` keeps the new rights and prefix grants in version 3, and a build that predates them refuses a file that uses them (#149).
- Add `SCAN CHUNKS ... WHERE condition`, which keeps the blocks for which the condition is true: without SINCE it lists only chunks with a matching block, with WITH DATA a form of those blocks; with SINCE, which then requires WITH DATA, it lists every changed identity with null where no block matches; LIMIT counts every chunk a page visits and the reply adds `after` to continue from (#147).
- Add `AGGREGATE ... WHERE condition`, which aggregates only the present blocks for which the condition is true, with block and chunk columns, positions, NOW() and typed `$n` parameters; inside a transaction every requested cell still joins the read set (#148).
- Add ALTER COLUMN ... SET DEFAULT, DROP DEFAULT, SET NULL, DROP NULL, SET REQUIRED and DROP REQUIRED, where DROP NULL first checks every stored value and refuses the first NULL with its block, and ALTER TABLE ... RENAME TO, which renames a table atomically with its epoch, data and slots, needs ADMIN on both names, moves its grants to the new name and ends its watches; manifests gain schema change kind 6 and DROP NULL check tag 2 (#145).
- SHOW STATUS reports the server version, uptime and read-only mode, each table with its state and fence reason, and in `fenced` the fenced tables whose features cannot be read. SHOW TABLE STATS adds `chunks`, `loaded_chunks`, `slots` and `watches`, and `files` and `disk_bytes` from a listing of the table directory that no other statement waits for, and SHOW SLOTS adds the durable `revision`, `lag_revisions` and `attached`, with a `PREFIX 'name'` filter (#149).
- Add `ALTER USER u ADD VERIFIER $1` and `ALTER USER u DROP OLD VERIFIER` to rotate a password without downtime: a user holds at most two verifiers with one salt and iteration count and logs in with either until DROP OLD VERIFIER; `ALTER USER u VERIFIER` and `chunkdb_admin reset-password` leave one; `chunkdb.users` is written as version 3 and version 2 files are still read; SHOW USERS reports `verifiers`, the number of verifiers of each user, and `alter_user` audit lines record the form that ran as `change` (#149).
- Add GET AREA ... SCALE k USING MAX | MIN | MODE | FIRST | ANY: each populated chunk comes back as a downsampled form with one sample per k blocks on every active axis, chunk form section 7 holding k and the reduction, and HELLO feature `area_scale`; k must divide every chunk side, NULL values are skipped except by FIRST, MAX and MIN skip NaN, MODE breaks ties by first occurrence, SET CHUNK refuses a downsampled form, and the response limit counts the downsampled forms (#148).
- WATCH without SLOT takes up to 64 areas, `AREA cx0 cy0 TO cx1 cy1, AREA ...`, and keeps a chunk inside any of them; watches without SLOT that have the same areas, COLUMNS, NO BEFORE and CHUNKS share each projected event and its encoded frame instead of filtering and encoding it for each watch; a slot keeps one AREA, so WATCH SLOT with several different ones returns `INVALID_ARGUMENT reason=slot_filters` (#146).
- Add `chunkdb_admin --data-dir <dir> rebuild-version-clock`, which replaces lost or malformed table clock files offline: it refuses while a server runs, on any other damage and on a feature this build can only read, keeps a readable clock above every revision on disk, and writes any other clock 2^32 revisions above the highest revision of the table's images, WALs, archives, coordinate files, intents and slots, or above the version floor; the server's refusal for a lost or malformed clock names the command (#149).
- The reference documents the ascending cx, cy, cz row order of SCAN CHUNKS and how to follow a scan with WATCH AFTER its first page's `epoch` and `position` (#147).
- Add `AGGREGATE CHUNK | AREA | AREA AROUND ... FROM t COUNT(*), SUM(a), MIN(a), MAX(a), AVG(a) [BY CHUNK]` over the present blocks of integer and float columns: a map of results, or with BY CHUNK one row per chunk; integer SUM is exact in 128 bits, NULL values are skipped, float MIN and MAX order NaN above every value; it covers at most `--max-area-chunks` chunks and replies within `--max-area-response-bytes`, and reads the transaction snapshot inside a transaction (#148).
- With a feed slot, checkpoints and the writes that wait on them no longer wait while a slot pass syncs the files written since the previous pass; a pass held checkpoint publication through all its syncs, so with many chunks written between passes a write could wait for seconds. A pass now sets the FLUSH WAL durability floor, so later relaxed-mode checkpoints of that store sync their images, as after FLUSH WAL or a reopen (#140).
- A connection that leaves a WATCH or WATCH ... SLOT with UNWATCH starts its `--idle-connection-timeout-ms` interval when UNWATCH is answered; before, a watch longer than that timeout made the server close the connection without a reply to its next request (#140).
- SHOW CONNECTIONS lists a connection that left its WATCH with UNWATCH as `idle`; before, it showed `watch` until the connection's next request.
- The published Docker image carries the OCI labels `org.opencontainers.image.title`, `version`, `revision`, `source`, `created` and `licenses` (#154).
- Serve idle connections, authentication and session controls without occupying statement workers, add cancellation and statement timeouts with user admission limits, and stream bounded large replies under output progress deadlines; a request waiting for the server's input credit has its frame deadline restart when the credit is granted, and one that waits longer than `--client-io-timeout-ms` receives `BUSY reason=input_budget` and closes, and after authentication a drained frame body must arrive whole within `--client-io-timeout-ms` of the end of its header, like a kept one, where each 4096-byte piece of it had a timeout of its own; a worker with no queued request waits for the next request of the connection it answered and gives it up when another request needs a worker (#137).
- A `--read-only` server refreshes the chunk list of GET AREA and SCAN CHUNKS after a writer change by reading only the chunks the writer changed, which the writer records in the volatile table file `chunkdb.snapshot.changes`, instead of reading every chunk of the table again; after a writer restart, COMPACT TOMBSTONES or more than 4096 chunk file writes since its last read, it reads every chunk once.
- Release a terminated slot watch's claim before its terminal reply or socket closure, so immediate reconnects after lost access or an output deadline do not race background cleanup and receive SLOT_BUSY.
- Refuse every write once the chunk version clock is exhausted instead of wrapping it: a ceiling at the top of the revision range no longer lets a later write take revision 0 and stop the server.
- Errors a first-time user meets say what to do next: AUTH_REQUIRED starts with the login step (the user in the URI, such as `chunk://admin@host:4242/`, and the password in the client) and keeps the HELLO detail after it; AUTH_FAILED says to check the user name and password the client sends or to reset the password with `chunkdb_admin reset-password`; TABLE_EXISTS suggests another name, IF NOT EXISTS or DROP TABLE; a coordinate count that differs from the table gives both counts; an unknown statement names GET or SET for SQL words such as SELECT and otherwise points to the CQL reference; an unsupported `--listen-uri` scheme names `chunk://` and `chunks://`. The quick start adds steps for a busy port, a rerun and a kept volume, and links the Go, Node.js and chunk-cli world examples (#152).
- Add RESTORE TABLE t FROM 'backup' [AS name] to restore one table of a completed backup into a running server as a new table with a new epoch and the backed-up epoch and cut as its lineage: it needs ADMIN on `*` or MANAGES USERS and `--backup-dir`, checks the table's inventory files, checksums and cut, appears only once complete, leaves nothing behind after a failure, server shutdown or crash, logs its progress and replies with the new epoch, lineage, files and bytes; add SWAP TABLES a, b to exchange two tables' names in one atomic directory exchange after making their writes durable, with ADMIN on both, ending their watches and open transactions, keeping epochs, slots and data with the tables and grants with the names, marking both tables' slots so that their next watch without AFTER starts with resync, and refused on Windows; a slot restored online or offline also starts its next watch without AFTER with resync, recorded as slot flag `0x80`; the audit log adds `restore_table` and `swap_tables` (#158).
- Stop RESTORE TABLE and SWAP TABLES on CANCEL, KILL CONNECTION and statement timeouts before they publish: a stopped restore leaves nothing restored, and a stopped swap leaves both tables under their names (#137).
- SHOW CONNECTIONS adds a `progress` field to each connection: null, or for a RESTORE TABLE from the start of its copy until the statement completes a map of `files_done`, `files_total`, `bytes_done` and `bytes_total` copied from the backup (#158).
- GET AREA with LIMIT or AFTER ends a page before a chunk too large for an empty page instead of refusing the rows before it; that chunk, as a page's first cell or in a plain area, is refused with `OUT_OF_RANGE reason=area_entry_too_large chunk=x,y[,z] required=n limit=n`, so a client reads it with GET CHUNK or fewer COLUMNS and continues AFTER it, including at the largest chunk geometry (#150).
- Measure many feed subscribers with `chunkdb_server_bench --watch-delivery measure`: a watch resync is counted instead of failing the run, a drain waits while pushes arrive, CREATE SLOT waits up to `--slot-create-timeout-ms`, and each result lists every watch with its events, resyncs, bytes, lag at the last write and catch-up time; watch readiness uses poll, so watches work beside descriptors numbered past FD_SETSIZE; the default `strict` delivery and its reports are unchanged (#140).
- `chunkdb_server_bench --failed-logins N` runs N clients that log in with a wrong password beside the measured clients, from when they have all logged in until they finish, and reports the failure and ban replies they received (#137).
- A conditional chunk mutation that has committed is no longer reported as failed when a later cleanup, checkpoint or snapshot warning fails; when a rejected conditional mutation cannot neutralize its WAL tail, the store becomes fail-closed before it logs, and the caller gets the original error.
- `--max-handshakes-per-ip 0` starts the server with the handshake limit off, as documented, instead of being refused; a negative or non-numeric value is refused.
- `--statement-timeout-ms 0` starts the server with no default statement timeout, as documented, instead of being refused; a value that is negative, not a number or above 86400000 is refused with a message naming the flag, before the data directory is created.
- A FLUSH that runs out of memory while it collects the files written without a sync keeps them all recorded, including the full-directory sync owed after the record overflowed, so the next FLUSH still syncs them; before, that failure could drop the record and a later FLUSH could return without syncing those files.
- A FLUSH whose sync fails and that then runs out of memory while it records the unsynced files again makes the next FLUSH sync the whole data directory; before, the files not yet recorded could be dropped and a later FLUSH could return without syncing them.
- A CREATE TABLE that fails after its table directory is published, including on a failure to allocate memory while the new table is set up, now removes that directory again, or fences the name until RECOVER TABLE or a restart if the directory cannot be removed, instead of leaving the name taken by a table the server does not serve.
- A failure to allocate memory while ALTER TABLE or TABLESET prepares to reopen a table now leaves the table serving its old definition, instead of leaving it with the new manifest and every later command on it waiting until a restart.
- A failure to allocate memory while DROP TABLE prepares its fallback now leaves the table served, instead of leaving every later command on it waiting until a restart.
- A failure to allocate memory while a refused column narrowing that cannot be removed prepares to fence the table now leaves the table served with the narrowing until a restart, instead of leaving every later command on it waiting until a restart.
- A narrowing refused by a value in a 3D table names its block as `block (x, y, z)`; it used to give two coordinates, with y counted across the chunk's depth.
- Accept ALTER TABLE ... ADD COLUMN ... REQUIRED without DEFAULT on a table whose chunks hold only chunk metadata, as documented, instead of refusing it as if blocks were present.
- On Linux and macOS, a writer lock that fails for a reason other than a lock held by another process is reported with that error (`failed to lock writer lock file: <path>: <reason>`) instead of as an active writer.
- Check a login's credentials when AUTH finishes it, not only at HELLO: a login whose user got a new verifier, was dropped or created again, or, for an unbound login, got REQUIRE CHANNEL BINDING in between fails with the AUTH_FAILED of a wrong password.
- A schema push from WATCH ... SLOT carries the table's `dims` and the chunk columns of its schema version, where it sent `dims=2` and empty `chunk_columns` for three-dimensional tables and tables with CHUNK COLUMNS.
- GET AREA and GET AREA AROUND inside a transaction, paged or not, read only the chunks the coordinate index lists or that a later write emptied, instead of probing every chunk of the area; the transaction still conflicts with later writes to any chunk of the area.

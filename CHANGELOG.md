# Changelog

## Unreleased

- Add configurable area and transaction chunk limits, exact area-response byte admission, and cursor paging for GET AREA; expose allocator-aware variable storage through `ChunkVars::Encode()` (#136).
- Add three-dimensional tables, typed chunk columns, checked sectioned chunk forms, atomic metadata and projected writes, and retained tombstone identities with incremental scans and explicit compaction (#133).
- Measure a slot change read back from the feed archive by the frame the watch sends: decoding skips chunks outside the slot's AREA, keeps only its COLUMNS and drops before values with NO BEFORE, and stops once that frame would exceed the current `feed_buffer_bytes`, so a filtered change whose frame fits is delivered; in CHUNKS mode, chunks outside the area no longer count toward the budget.
- Bind SCRAM logins to their TLS connection (SCRAM-SHA-256-PLUS): a client-first message starting `p=tls-exporter,,` (RFC 9266, TLS 1.3) or `p=tls-server-end-point,,` (RFC 5929) is checked against the server side of the connection, and a login relayed by something that ends TLS fails with `AUTH_FAILED reason=channel_binding`; `--auth-channel-binding require` refuses unbound logins with `AUTH_REQUIRED reason=channel_binding`, `CREATE USER ... REQUIRE CHANNEL BINDING` and `ALTER USER ... [NO] REQUIRE CHANNEL BINDING` do it for one user, SHOW USERS adds `requires_channel_binding`, the audit log adds the login reasons `channel_binding` and `channel_binding_required`, HELLO lists the capability `channel_binding`, and `y,,` is refused on TLS and accepted without it (#162).
- Add `chunkdb_chunk_map_bench`, which times point reads and writes across many loaded chunks and inside one chunk, and the two chunk-map lookups alone, on a warm cache; docs/design/COLUMNS_DESIGN.md states the method (#135).
- Resolve configured Windows directory junction roots and extended paths for backup and restore while refusing descendant reparse points (#150).
- Add the event journal guide, docs/EVENT_JOURNAL.md: keep every change from a durable slot in your own store, acknowledging only after the store syncs, rebuild the world at a revision or commit time from a base snapshot, render a timelapse, retain segments and snapshots, and resume after a crash (#153).
- Lower the peak memory of SET CHUNK: a whole-chunk write moves the state it replaces into the transaction history instead of copying it and frees it before an inline checkpoint, stages its WAL frame in one buffer sized once, and builds the checkpoint image without intermediate copies; in a transaction, the written-chunk limit, `--txn-max-bytes` and `--txn-total-bytes` are checked by the smallest size of the state the form writes before the form is decoded or the chunk is read.
- Deliver a slot change larger than the watch's share of `feed_buffer_bytes` instead of ending the slot watch with OUT_OF_RANGE when many watches share the table: the change waits until the watch has sent its earlier output and is then queued from a separate table pool of `feed_buffer_bytes`, so queued feed output per table stays within twice that budget apart from frames admitted before a new watch reduced the shares, waiters take the pool in arrival order, and a connection sending any frame larger than its share (changes, schema, progress and resync) that writes no byte for `--client-io-timeout-ms` is closed to free the pool, where on TLS each completed record of up to 16 KiB counts; only a change or schema frame that, with its ACK TIMEOUT record when set, is larger than the budget still ends the watch with OUT_OF_RANGE.
- Give each durable slot an owner, saved in its slot record: the user running CREATE SLOT, or the user named by its new `OWNER user` suffix, also inside MIGRATE and its recovery; WATCH ... SLOT by another user, with or without AFTER or TAKEOVER, needs ADMIN on `*` and otherwise answers PERMISSION_DENIED without changing the slot; SHOW SLOTS reports `owner`, backup and restore keep it, and DROP USER leaves slots unchanged; a slot without a recorded owner takes the user of its first granted attach without ADMIN on `*`, a watch of a slot its user does not own ends when that user loses ADMIN on `*`, SHOW SLOTS shows an owner to that user and to MANAGES USERS only, CREATE SLOT IF NOT EXISTS with another OWNER is refused like different filters, and a slots file records owners in its format 4 layout next to the table dimensionality, so earlier slots files (formats 1 to 3) are refused as earlier development layouts.
- Apply rights changes to open watches and to sessions of dropped users: a watch ends as soon as its user loses READ on the table, with a best-effort NO_TABLE, before any later push and without accepting a later ACK; when a user is dropped, its open watches end at once with a best-effort `AUTH_REQUIRED reason=user_dropped`, its other sessions answer their next statement with that error, and each connection closes; a user created again under the same name gives those sessions no rights, and they cannot change its password.
- End a transaction that has run a table statement once it is past `--txn-max-duration-ms`, at the next statement its connection runs (PING, DESCRIBE and BEGIN included) or when another transaction's write finds `--txn-total-bytes` full, so an expired transaction whose client sends nothing or only PING no longer keeps other connections' transactional writes failing; its COMMIT answers CONFLICT reason=duration and applies nothing, as before, and a transaction without a table statement still answers PING and an empty COMMIT as before.
- A successful login clears only the failed logins of its own user name from its source address, so logins under one account no longer reset the failures for another name toward `--auth-ban-failures`; a source tracks failures separately for at most 8 names at a time, and failures for further names are cleared by no login; when a ban ends, the source's failures are reset instead of each later failure banning it again.
- Scope recorded migration names to the rights of the change they record: MIGRATE under a name recorded for a table without the caller's ADMIN, or for GRANT or REVOKE without MANAGES USERS, answers PERMISSION_DENIED whatever statement it submits instead of skipped or MIGRATION_MISMATCH, and SHOW MIGRATIONS no longer requires MANAGES USERS but lists only the records within the caller's rights, with the applying user shown only to MANAGES USERS.
- Check stored values for a narrowing inside MIGRATE before catalog admission, under the table lease as plain ALTER does, so CREATE, DROP, ALTER, MIGRATE, RECOVER TABLE and SHOW MIGRATIONS of other tables no longer wait for the check; BACKUP, ENABLE FEATURE and SHOW STATUS started during the check still wait for it. Writes to the column must fit the narrower type during the check, and the step is decided only if the table schema is unchanged since the check. A refused narrowing, with or without MIGRATE, leaves no ledger record and removes its narrowing again; if that removal fails, the statement still returns its refusal and the table is fenced until RECOVER TABLE or a restart, instead of keeping the narrowing and refusing every later one.
- A `chunks://` listener limits TLS 1.2 to ECDHE key exchange with AES-GCM or ChaCha20-Poly1305 ciphers, so every TLS 1.2 session has forward secrecy; TLS 1.3 suites and `--tls-min-version` are unchanged.
- BACKUP TO refuses, on Linux and macOS, a `--backup-dir`, an existing directory below it or an existing destination that is not owned by the server user or root or is writable by group or others, checking each directory as it is opened, so only the server user or root can replace files in a backup.
- `chunkdb_admin reset-password` refuses a backup or an incomplete restore directory before it takes the writer lock, with the error the server gives, so the backup stays restorable.
- Keep memory bounded by `--max-loaded-chunks` when reads touch new chunks: the check for two live objects of one chunk now forgets a chunk once its object is freed, instead of keeping about 430 bytes for every chunk coordinate ever loaded.
- Check a column type against its size range before its DEFAULT is read or encoded in CREATE TABLE, ADD COLUMN and ALTER COLUMN TYPE, so a type such as `u0` or `bits(4294967288)` is refused with its range instead of another error or a large allocation; a narrowing refused by a value names a block past the int64 range on an axis as `[chunk, local]`, as WATCH does.
- Bound everything before authentication by the HELLO deadline: HELLO, AUTH and all their parameter frames must arrive within `--client-io-timeout-ms` of the connection's start, where each frame used to start a timeout of its own; before authentication HELLO takes at most 12 parameters.
- Bound verifier salts to 16 through 256 bytes in CREATE USER, ALTER USER and the users file, limit a quoted VERIFIER to 512 bytes like `VERIFIER $1`, refuse GRANT on a name that is not a valid table name, and refuse a users file with an out-of-range salt or an invalid user or table name instead of writing a salt length that does not fit its field.
- Add matched-subscriber budget comparisons with `chunkdb_budget_compare --watch-both TABLE[:N][:slots]` and require a control with the same subscriber settings (#140).
- Add extensible reply metadata, exact unsigned revisions, HELLO options, persistent watch filters, ACK deadlines, takeover, lineage, and explicit feature activation (#69).
- Keep feed subscribers off the write path: a feed wakes the slot catch-up worker only for slot watches, once per scan and when a slot watch starts, notifies watches only when a scan publishes changes, stops a slot watch's steps when one changes nothing, counts every slot's retained bytes from one archive listing, and syncs only the files written since the last durable-frontier pass after a store's first, including those a rollback boundary is still syncing; `chunkdb_server_bench --watch TABLE[:N][:slots]` opens several ordinary or slot watches for the subscriber budget (#140).
- Flush and checkpoint an evicted chunk without holding its large-chunk lock, so loads of the other chunks in that large chunk no longer wait for the checkpoint's syncs, except while the table has feed slots, when a load still waits for the checkpoint's publish step; `chunkdb_large_world_bench --scenario evict-load` reports their cold-load latency percentiles during eviction checkpoints (#143).
- Add `--read-only` to serve a data directory, next to its writer, or a completed backup without writing to it: no writer lock, recovery, checkpoints, maintenance or revision reservations; statements that change anything answer INVALID_ARGUMENT, a directory that needs recovery is refused with a message saying so, a backup is checked against its inventory before it opens, the users file and its permissions stay as they are, and a chunk read once is kept and read again only after the writer changed its table; a reader probing a table no longer makes a starting writer fail as if another writer held it (#157).
- Bound FLUSH WAL and clean shutdown time on large worlds: the barrier syncs from up to 16 threads, no longer blocks checkpoints while it syncs except on Windows, and above 65,536 tracked files tracks changed large-chunk directories instead of syncing the whole table directory; a rollback that replaces a hard-linked WAL after a barrier syncs the new entry at once (#141).
- Add RECOVER TABLE to recover a fenced table without a restart while other tables keep serving: a table left out of service by a failed ALTER, DROP or CREATE, with a fail-closed store or a failed snapshot generation, or after a failed feed cleanup; SHOW TABLES lists fenced tables, DESCRIBE reports why one is fenced, backups refuse a fenced table, and watches of a fenced or recovered table end with INTERNAL instead of NO_TABLE (#159).
- Log how much of the reply the socket took when a connection misses its reply write deadline (`reply write deadline exceeded after <written> of <size> bytes`) (#130).
- Record the host name in the writer lock metadata, so a process on another host does not take over a writer whose heartbeat is under 5 seconds old because no local process has its pid; metadata without a host name keeps the pid check (#150).
- Remove staging left by failed or interrupted backups when the next backup starts, not only at server start; a start that cannot remove backup staging logs a warning instead of refusing to open, entries holding a backup marker or guard are kept, and catalogs opened without the writer lock leave backup staging in place (#150).
- Add `--audit-log` for logins and administrative statements as JSON Lines, reopened on SIGHUP; `--slow-statement-ms` for WARN lines on slow statements; `--auth-max-failures-per-connection`, `--auth-ban-failures` and `--auth-ban-ms` for the login limits; and `--proxy-protocol v2` to take client addresses from PROXY protocol v2 headers (#69).
- Format metric durations and bucket bounds without the C library's locale-dependent number formatting, so `SHOW METRICS` always uses a `.` decimal separator (#150).
- Builds without tests (`-DCHUNKDB_BUILD_TESTS=OFF`, as the release binaries and the Docker image are built) leave out failure injection, so the engine no longer reads `CHUNKDB_FAILPOINT_*` environment variables on its write and flush paths; `CHUNKDB_FAILPOINTS` sets it explicitly (#142).
- Publish stable read-only snapshot generations through a mapped counter when the last artifact transition finishes, without an idle timer or per-write metadata sync (#69).
- Sync the data directory before relying on a feed archive directory this store did not create, so a preparation that failed before syncing it cannot leave archived WALs in a directory whose entry may not survive a crash (#69).
- Add opt-in libFuzzer targets (`-DCHUNKDB_FUZZ=ON`) for request framing, CQL, WAL frames, chunk images, chunk forms, manifests, slot records, migration records and backup markers, run for 30 seconds on every pull request and nightly for longer, with crash inputs kept in `fuzz/regression` and replayed by `ctest` without libFuzzer; request parameter framing now has one implementation shared by the server and the fuzz harness, and the chunk form decoder is shared with the engine (#163).

- Add the expression engine for conditions and computed assignments: parsing, typing and exact evaluation with three-valued NULL logic, not yet used by statements (#69).

- Add RELOAD TLS, also run by SIGHUP on Linux and macOS when a `chunks://` listener is configured, to load a renewed TLS certificate and key for new connections without a restart, and `--tls-min-version 1.2|1.3`; the certificate file may hold intermediate certificates after the server certificate, and they are sent to clients (#69).
- Preserve queued terminal slot-watch errors when an acknowledgement arrives during shutdown (#69).

- Evict the oldest retained ordinary feed history before refusing a write capture, so watches that keep up no longer resync when the live feed budget is full (#69).

- Build and test native Windows with MSYS2 UCRT64; binaries use the Universal C Runtime included in Windows 10 and later (#69).
- Rewrite user guides and statement references with checked CLI examples and publish a major Docker image tag (#68).
- Limit connections before HELLO to 64 per source by default, create data and backup files/directories with owner-only access (including Windows ACLs), tighten existing users-file permissions at startup, and obtain salts/nonces directly from the operating system random generator (#63).

- Cancel pending Windows socket I/O when stopping active connections, and prevent dequeued connections from becoming active after shutdown (#69).

- Publish server shutdown under the pending-worker mutex so idle workers cannot miss the stop notification (#69).

- Prevent feed I/O shutdown from waiting indefinitely when Stop wakeups are drained before socket polling (#69).

- Remove an ordinary WATCH subscription and establish its linger policy before acknowledging UNWATCH (#69).

- Persist per-table live feed and durable-slot byte limits, expose effective limits in DESCRIBE and apply ALTER limits to existing feeds and slots (#65).

- Start fresh servers without tables, use explicit table definitions for geometry, remove the unsupported shared-writer server switch and recognize only current backup staging names (#60).

- Return null for unwritten chunks, default table chunks to 16 x 16, allow required columns without defaults on empty tables, include narrowing ranges, apply comma-separated rights atomically and accept trailing CQL options in any order (#69).

- Bound SET BLOCK parameter frames by their actual declared lengths, accepting small values in columns with large maxima while refusing an oversized total before reading its payload (#63).

- Bound the parameter frames of one statement together, write `chunkdb.users` readable by its owner alone, bound a verifier's iteration count, refuse TLS renegotiation and bound a chunk image section's declared size.
